# 故障对照：保留现场经验，避免“一个现象只对应一个原因”

## Peach 首次登录与安全门

- **现象**：配置/初始化访问被 403 拒绝；**先查** Peach 镜像版本、请求路径、来源是否公网、是否存在转发头、是否已登录；**建议** 通过 SSH 隧道或私有网络打开、按该版本官方说明取本机登录口令。
- **不要做**：反向代理伪造本地源、修改或剥离请求头以绕过 Peach 安全控制。`PEACH_ACCESS_PASSWORD` 设置访问密码，不会让所有公网来源获得管理权限。
- **版本差异**：旧现场包含首次设置提问页，新 Docker 文档也明确有生成的登录口令与 `peach token`；运行中依据实际版本，不要硬编码单一首次设置流程。

## 媒体挂载看不到文件

1. 宿主机验证目标媒体真实文件可读；CloudDrive2 UI 已经完成挂载，不能仅看空目录。
2. 查 `findmnt -o TARGET,PROPAGATION <宿主媒体目录>`，确认宿主共享传播；CloudDrive2 使用 `rshared` 让子挂载出容器，Peach 使用只读 `rslave` 接收子挂载。
3. 检查 Peach 实际 `docker inspect` bind 是否老配置、Peach UID1000 是否有目录遍历与文件读取权；必要时先备份再 recreate，而非只 `restart`。
4. 真正读取同一个文件，不要仅比较“文件数”；重启后重新测试。
5. Docker Desktop 不支持该机制；改稳定媒体目录/SMB/远端 Linux，不要无限调整传播标志。

## CloudDrive2 启动失败

- 查 `/dev/fuse`、特权策略、宿主传播、SELinux/AppArmor/NAS 内核；fnOS 的容器内 FUSE namespace 限制优先选原生包。
- 原厂例子有 `network_mode: host`；本包用桥接网络便于限制管理端口，因此需目标机验证。**绝不擅自切换到 host network**，否则 19798 的网络暴露会改变；需用户批准、防火墙审查，并更改 Peach API 地址。

## CloudDrive2 API/离线下载

- 从 Peach 容器检查 `http://clouddrive2:19798` 可达（若容器共享同一网络）。外部已有 CD2 则使用实际局域网地址和可达端口。
- 令牌检查错误可能来自 root 非 `/`、权限不足、目标云目录、云盘侧能力或 API 版本；历史 InstaBox/115 案例中 root `/` 有效，但不是所有设备与云服务的通用要求。
- 云端目标目录（示例 `/115open/云下载`）与 Peach 媒体目录（示例 `/media/云下载`）不同；推送发现前缀应在 UI 关联云路径与媒体源。
- 后台通知可能依赖 CD2 会员；未能使用实时 webhook 时可以计划扫描，但不得假设即时入库。
- 先验证真实下载权限、配额、目标可写和任务状态；`remote_done` 只是云端完成，仍需验证 `ingested` 与实际文件访问。

## 扫描任务“失败”但数据已有

- 查任务错误是否是元数据站点限流；读取日志和资料数量、记录失败的特定条目；若确认部分成功，在限流结束后补跑，不要无条件重建库或反复保存配置。
- 如果数据库只读查询，优先用 Peach 官方公开运维说明确认库路径/模式；不使用硬编码内部 SQL 结构操作生产数据库。

## Jackett / Torznab

- Peach 官方接受 Jackett 或 Prowlarr；先在索引器控制台测试合法、已知可得的查询，再在 Peach UI 对照。
- feed URL 只填写协议 + 可达主机 + API 路径，不要带 `?apikey=...` 等查询字符串；key 使用独立字段。
- 0 个结果先看 Jackett 日志、站点响应、登录、控制查询；只有管理器可搜、Peach 无法查时才重点检查容器地址、密钥和接口配置。
- 不承诺任何站点或具体资源一定存在；保留搜索失败与下载失败的独立诊断。

## InstaBox 休眠/断线

- 分辨空闲暂停、人工暂停、运行时长限制与磁盘压力；根据当前官方 API/CLI 文档查询状态与恢复方式，避免对用户保证“访问端口一定能唤醒”。
